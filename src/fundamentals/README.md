# Fundamentals

Project-independent runtime vocabulary.

Fundamentals have no locus. Betwixt, Workshop, Crucible, Observatory, and future projects may instantiate or compose them, but none owns them.

A Fundamental may be internally complex. Independence from a particular project or place—not simplicity—is what makes it fundamental.

Current vocabulary grows vertically from things that have earned reuse:
- `materials.js`, `cameras.js`, `lights.js` — inert/runtime descriptors.
- `liquids/` — authoritative liquid state, behavior, queries, and presentation.
- `terrain/` — deformable scalar-field terrain plus earned initialization treatments; Functional Biomes compiles bounded heterogeneous virgin functions into ordinary mutable terrain under a frame budget.
- `bearings/` — high-count matter behavior and presentation.
- `consequences/` — compositional runtime consequences of Fundamentals encountering one another.
- `relations/` — semantic nodes, ports, connections, composition, and projections. This is the substrate for snapping-point construction.

Relations are topology before geometry. A named port or connection may later be satisfied by projection, constraints, joints, IK, bones, or rigging without changing what the relation means.

New work may start here. Legacy code is not migrated merely for cleanliness; existing capabilities graduate only when reuse creates pressure.

Everything here is runtime-native. Categories appear only when repeated use earns them.
